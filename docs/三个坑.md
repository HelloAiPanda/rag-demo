# 三个坑：故意改坏，再修好

> 这三个坑是我做完 Demo 之后**故意复现**的，目的是在面试里能讲「我改了什么」。
> 每个坑都给出：怎么改 → 会看到什么 → 为什么 → 怎么修。

---

## 坑 1：把切片从 500 改成 2000

**改**：`.env` 里 `CHUNK_SIZE=2000`

**现象**：问「流式对话为什么不能边生成边写数据库」，返回的答案里混进了声纹、上传、监管的内容；问细节问题时答非所问。

**原因**：切片太大，一个块里塞了三四个主题。检索按整块算相似度，块里只要有一个词命中就整体排前，模型拿到一大段噪声，抓错重点。

**修**：切回 500，保留 100 字重叠。判断标准不是「块大不大」，是「一块里是不是只讲一件事」——按段落切就是为了这个。

---

## 坑 2：把拒答阈值去掉

**改**：`MIN_SCORE=0`（等于永不拒答）

**现象**：问一个文档里根本没有的问题（比如「年假几天」），它照样从别的段落里摘一段出来，看起来很像答案。

**原因**：没有阈值就没有「不知道」这个出口。向量检索永远会返回 top-k，哪怕全是噪声——因为余弦相似度不会返回空。

**修**：设 `MIN_SCORE=0.18`，低于阈值直接返回「资料里没有找到相关内容」。**拒答不是失败，编造才是事故**——这条在银行场景比准确率更重要。

---

## 坑 3：去掉重复文档的指纹校验

**改**：`app/rag.py` 里注释掉 `existing = self.index.find_by_sha(sha)` 这段

**现象**：同一份文件传两次，库里出现两份，检索时同一条内容命中两次，答案里重复引用。

**原因**：按时间生成 doc_id，没有内容指纹，系统分不清「同一件事」和「两件事」。

**修**：入库前用 `sha256(raw)` 查重，命中就跳过。这和培训平台里「任务重复消费」是同一个病——**所有写操作都要有幂等键**。

---

## 怎么用这三段

面试时不要主动念，等他问「你遇到过什么问题」。然后按这个结构讲 90 秒：

> 现象 → 我怎么发现的 → 根因 → 怎么修 → 后来加了什么规范

三个坑对应三种能力：

- 坑 1 = **检索质量**（切片策略）
- 坑 2 = **安全边界**（拒答）
- 坑 3 = **写入幂等**（数据一致性）

正好覆盖 RAG 工程里最常被问的三块。
